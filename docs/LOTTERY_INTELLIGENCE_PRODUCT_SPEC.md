# AI 彩票与体育彩票数据研究平台 — 产品需求与技术方案

> 项目代号：WeiRuan Lottery Intelligence（暂定）
> 文档版本：1.0
> 状态：产品规划稿
> 核心原则：数据可核验、分析可解释、回测可复现、不承诺中奖、不销售或代购彩票。

## 1. 产品定位

建设一个面向成年用户的中文彩票与体育赛事数据研究平台，覆盖福利彩票、体育彩票数字型玩法，以及足球/篮球赛事数据研究。平台提供历史开奖档案、统计可视化、概率与规则计算、组合校验、AI 研究报告、回测与赛果复盘。

产品不是彩票发行或销售机构，不接收投注，不代购、不组织合买，不宣传“必中”“稳赚”“内部杀号”等误导性内容。所有预测/推荐相关模块都应标注为“模型研究/娱乐参考”，不得暗示能改变随机开奖概率。

## 3. 目标用户与使用场景

1. 研究历史开奖规律的成年用户：查询开奖、统计号码出现次数、遗漏、分布。
2. 重视数据透明度的用户：查看计算口径、样本区间、数据源、更新时间。
3. 体育赛事爱好者：比较球队近期表现、主客场、进失球、伤停与赛程。
4. 内容编辑：引用有来源、可追溯的赛果与历史统计图表。

## 5. 核心功能详细需求

### 5.1 开奖历史数据库
每条开奖记录至少包括：
- game_code、issue_no、draw_at、main_numbers、bonus_numbers
- sales_amount、jackpot_amount、prize_tiers（字段可空）
- source_id、source_url、source_published_at、fetched_at
- verification_status、raw_payload_hash、created_at、updated_at

规则：
- 期号 + 彩种作为唯一键。
- 原始数据与标准化数据分层保存。
- 保留原始响应/快照及哈希，支持追查。
- 更正开奖信息时保存版本，不静默覆盖。
- 不确定字段保持 null，不可臆造。
- 官方源为主；可用第二来源比对号码和期号。冲突记录进入人工复核队列。
- 展示“官方已核验 / 多源一致 / 单源待核验 / 数据异常”等状态。
- 页面显示数据截止时间和最近抓取时间。

### 5.2 统计分析模块
所有统计均可按最近 30/50/100/200 期、自定义区间和完整历史切换：
- 单号频次、频率、理论期望次数、与理论值的偏差
- 当前遗漏、历史最大遗漏、平均遗漏、遗漏分布
- 奇偶比例、大小比例、和值、跨度
- 分区分布、连号数量、同尾、重号
- 两两/三数组合共现（显示样本量，避免过拟合误导）
- 位置分布（适用于有位置意义的玩法）
- 开奖矩阵、走势图、分布直方图、时间序列图
- 样本量不足时明确提示，不生成确定性结论。

定义：
- 频次 = 指定区间内号码出现次数。
- 遗漏 = 从最近一期往前到该号码上次出现之间的期数；当前遗漏不代表“即将出现”。
- 理论期望频次按每期边际概率 × 期数计算。
- 号码“热/冷”只是样本内描述标签，不是未来概率提升或降低的证据。

### 5.3 组合研究与校验
- 用户可手动录入号码、粘贴多注或导入 CSV。
- 自动检查号码范围、重复项、前后区数量、格式。
- 与历史开奖号码比对，显示历史命中情况。
- 组合构造器支持用户自定义约束：奇偶、和值区间、分区数量、固定号/排除号、连号数量。
- 随机生成必须标明“随机组合”；历史频率加权生成必须明确标明权重规则。
- 过滤条件只改变展示的组合集合，不提高单注中奖概率。
- 展示每注组合的理论概率与总成本（规则和票价有官方依据时）。

### 5.4 概率与奖金计算器
- 按官方当前玩法规则和奖级规则计算概率。
- 公式与输入项可展开查看。
- 区分单注概率、至少中任一奖级概率、头奖概率。
- 追加投注、多倍投注、复式/胆拖规则单独建模。
- 奖金、税费、奖池分配仅在规则和数据明确时计算；显示规则版本与生效日期。
- 不将历史开奖频次换算成未来中奖概率。

### 5.5 AI 分析引擎
AI 只能围绕有证据的数据生成解释，不可制造预测准确率。
输出结构：
1. 本次分析对象、数据区间、数据源与更新时间。
2. 描述性发现（数字事实、统计量、可视化引用）。
3. 模型/规则说明（计算方法、参数、版本）。
4. 不确定性与样本局限。
5. 参考组合（可选；注明随机/约束生成，不称为高胜率）。
6. 责任提示。

建议分层：
- L0 规则计算：开奖规则、概率、号码校验。
- L1 描述统计：频次、遗漏、和值、分区。
- L2 统计检验：卡方检验、置换检验、置信区间；多重比较校正。
- L3 机器学习：仅针对可验证任务（如体育赛果概率），进行严格时间切分、概率校准和基线对比。
- LLM 负责解释查询结果，不直接凭语言模型“猜号码”。

### 5.6 体育赛事分析
第一期只做信息与概率研究，不接入下注、投注单或支付。
数据：
- fixture、league、season、kickoff_at、home_team、away_team
- recent_form、home_away_stats、goals_for_against
- lineups、injuries、rest_days（仅有供应商数据时）
- odds_history（若法律允许且数据授权）
模型：
- 足球可从 Poisson 进球模型、Elo、逻辑回归开始。
- 篮球可从 Elo、攻防效率、节奏调整模型开始。
- 训练数据按比赛时间排序，严格避免未来数据泄漏。
- 输出概率分布及置信/不确定性区间，显示基准模型比较。
- 使用 Brier Score、Log Loss、校准曲线、按赛季滚动回测评价。
- 不发布“稳胆”“包中”等文案。

## 6. 页面与交互设计

视觉方向：专业数据终端，深蓝/石墨色背景 + 明亮高对比强调色；同时提供浅色模式。避免拥挤和彩色噪声。
- 桌面端：左侧主导航、顶部全局搜索、中央内容区、右侧数据说明/更新状态。
- 移动端：底部导航或折叠菜单，图表可横向滚动，表格转卡片。
- 首页用卡片呈现最新开奖、日历、数据状态、报告摘要。
- 每个图表可查看指标定义、时间范围和数据源。
- 不用“中奖率提升 XX%”作营销指标。
- 可访问性：键盘操作、足够对比度、图表文字摘要、响应式布局。

## 7. 技术架构建议

建议独立新建仓库，例如 `weiruan-lottery-intelligence`，不要直接把现有 `weiruan-AI` 聚合器改造成彩票站。

推荐架构（可按现有团队技术栈调整）：
- 前端：Next.js + TypeScript + Tailwind CSS + shadcn/ui + ECharts。
- 服务端：Next.js Route Handlers 或 NestJS。
- 数据库：PostgreSQL；Redis 用于缓存、队列与限流。
- 数据采集：Python workers（httpx/BeautifulSoup/Playwright 视官方页面而定），优先官方 API/公开下载文件。
- 任务队列：BullMQ / Celery；定时抓取、失败重试、告警。
- AI：统一模型网关，支持 OpenAI、Claude、DeepSeek 等；模型 API key 只保存在服务端。
- 部署：Docker Compose 起步；后续按流量拆分服务。
- 监控：结构化日志、采集成功率、数据延迟、错误率、API 耗时。
- 安全：服务端密钥管理、输入验证、速率限制、审计日志、备份与恢复演练。

## 9. 数据更新与质量保障

建议开奖后触发采集，同时每日执行全量/增量核验：
1. 按彩种开奖日历触发任务。
2. 请求官方数据源并保存原始快照。
3. 解析并做规则验证（号码个数、范围、格式）。
4. 与历史记录去重。
5. 可用第二源交叉校验；不一致则隔离，不写入“已核验”。
6. 更新统计缓存与报告。
7. 发送采集成功/失败告警。
8. 定期回补历史数据并抽样人工核验。

质量指标：
- 最新期数据延迟
- 采集成功率
- 解析失败率
- 多源一致率
- 历史缺期数
- 更正记录数量

不得绕过网站访问条款、验证码、登录限制或版权限制；对外展示和再分发需确认数据授权与当地合规要求。

## 11. SEO 与内容运营

每个彩种建立独立、可索引页面：
- 最新开奖与历史开奖查询
- 近 30/50/100 期统计
- 玩法规则与概率解释

## 12. 商业化边界

可考虑：
- 免费：历史开奖、基础统计、规则说明、组合校验。
- 会员：高级筛选、长区间导出、个性化研究报告、体育数据高级面板。
- B2B：数据可视化组件/API（必须确认数据授权）。
- 广告：仅展示合法合规广告，避免针对脆弱群体诱导投注。

禁止：
- 代购彩票、资金托管、彩票交易撮合。
- 保本、稳赚、保证中奖、内幕消息等宣传。
- 借 AI 伪造精确命中率或将回测结果冒充真实收益。

上线前须针对运营地区核对彩票、博彩、广告、消费者保护、隐私及数据再分发法规；必要时取得专业法律意见。年龄门槛与责任博彩提示应按适用法律实施。

## 13. 责任使用与透明度

全站固定说明：
“本平台提供公开开奖数据整理、历史统计与体育赛事信息研究，仅供成年用户学习和娱乐参考。彩票开奖结果具有随机性，历史数据、冷热号、遗漏值和模型输出不能预测或保证未来开奖结果，也不会提高单注中奖概率。请以发行机构官方公告为准。请理性参与，量力而行。”

AI 输出必须同时显示：
- 数据来源及链接
- 数据时间范围
- 最后更新时间
- 算法/模型版本
- 计算口径
- 是否经过回测
- 回测区间、样本量与基准结果
- 不确定性说明

## 14. 开发路线图

**阶段 0 — 可行性与合规（1 周）**
- 确认运营地区、彩种清单、数据授权。
- 验证官方数据入口、字段和更新频率。
- 完成 UI 原型与数据字典。

**阶段 1 — 数据 MVP（2–3 周）**
- 双色球、大乐透、福彩3D、排列三。
- 数据采集、核验、开奖档案。
- 频次、遗漏、和值、奇偶、号码矩阵。
- 响应式首页和数据状态页。

**阶段 2 — 分析工具（2–3 周）**
- 组合校验、概率计算、组合生成。
- 图表交互、数据导出、方法论。
- AI 统计摘要和自然语言查询。

**阶段 3 — 体育赛事（3–5 周）**
- 足球赛事与球队数据。
- 篮球赛事数据。
- 赛前研究、赛后复盘、概率模型验证。

**阶段 4 — 会员与规模化**
- 用户账号、收藏、订阅、个性化仪表盘。
- 性能优化、缓存、审计、监控、数据备份。
- 合规审查后再开放商业化功能。

## 15. MVP 验收标准

- 至少 4 个彩种的开奖数据可追溯到来源与抓取时间。
- 期号唯一、历史记录无重复，号码范围校验通过。
- 数据源冲突记录可隔离并人工复核。
- 统计值通过独立测试样本验证。
- 概率计算结果可由公开公式复算。
- 每张图表显示区间、样本数、定义与更新时间。
- AI 报告不生成无来源事实、不宣称保证命中。
